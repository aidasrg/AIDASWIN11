Dažniausiai užduodami klausimai (DUK)

Svarbiausi atsakymai apie BIOS virtualizaciją, Rufus NTFS nustatymus ir saugų WSA atnaujinimą.

1. Kodėl būtina įjungti BIOS virtualizaciją ir kaip ją rasti? +

Nors autounattend.xml apeina TPM 2.0 ir Secure Boot patikras, pats Windows Subsystem for Android (WSA) veikia lengvoje „Hyper-V“ virtualioje aplinkoje. Be procesoriaus aparatūrinės virtualizacijos Android branduolys nepasileis.

Kaip įjungti: Įjungdami kompiuterį spauskite Del, F2 arba F10, eikite į Advanced / CPU Configuration skiltį ir nustatykite Intel Virtualization Technology (VT-x) arba AMD SVM Mode į Enabled.

2. Kodėl programoje Rufus būtina rinktis NTFS ir nuimti visas varneles? +

Dėl NTFS: Senesnė FAT32 failų sistema nepalaiko didesnių nei 4 GB failų. Kadangi į ISO integruotas WSA paketas ir ADB, install.wim failas viršija 4 GB ribą – pasirinkus NTFS, Rufus automatiškai prideda UEFI:NTFS paleidiklį, todėl USB be problemų pasileidžia šiuolaikiniuose kompiuteriuose.

Dėl varnelių nuėmimo: Paspaudus START, Rufus iššokančiame lange siūlo sukurti savo autounattend.xml. Jei paliksite varneles, Rufus perrašys jūsų sugeneruotą AIDASWIN11 konfigūraciją (kurioje jau yra Win 11 Pro raktas, vartotojas ir klaviatūros).

3. Kaip vėliau atnaujinti WSA versiją neprarandant jau įdiegtų Android programėlių? +

Niekada nešalinkite WSA per Windows nustatymus (Uninstall), nes tai ištrins virtualų diską userdata.vhdx su visomis programėlėmis. Vietoj to atlikite atnaujinimą ant viršaus:

  1. Išjunkite WSA per nustatymus (Turn off) arba komanda WsaClient.exe /shutdown.
  2. Išpakuokite naują to paties kūrėjo (pvz., MustardChef WSABuilds) archyvą tiesiai į C:\AndroidSetup ir perrašykite senus failus.
  3. Paleiskite PowerShell kaip administratorius ir įvykdykite perregistravimą:
Add-AppxPackage -ForceApplicationShutdown -ForceUpdateFromAnyVersion -Register "C:\AndroidSetup\AppxManifest.xml"
4. Ką daryti, jei dukart spustelėjus .APK failą ADB rašo „cannot connect to 127.0.0.1:58526“? +

Tai nutinka tik tada, kai WSA nustatymuose dar nebuvo įjungtas Developer mode arba pati WSA posistemė dar nespėjo pilnai užsikrauti. Atidarykite Windows Subsystem for Android Settings → Advanced settings, įjunkite Developer mode, spustelėkite Manage developer settings ir pakartokite .apk paleidimą.
